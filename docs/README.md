# Архив: FrameDate — браузерная итерация 01

Локальный desktop-first редактор постановки боевых приёмов на примитивах для Shadow Fight 4: Arena. Это не Unity-плагин и не редактор игровых ассетов: после создания снимка проект открывается без SF4.

## Стек и запуск

Выбран один стек: **современный браузер + ES-модули без внешних зависимостей + встроенный Node.js HTTP-сервер**. В текущей Windows-среде доступны Node.js и браузер, но нет доступных npm/.NET-инструментов для воспроизводимой сборки Electron/WPF. Такой стек сохраняет независимый от UI расчёт, даёт полноценный оконный desktop-first интерфейс, не требует сети и создаёт переносимую папку. Сервер нужен только для явного чтения выбранного SF4-корня и атомарной записи JSON/HTML; интерфейс и экспорт не используют сетевые ресурсы.

Запуск из этой папки:

```powershell
node server.mjs
```

Откройте `http://127.0.0.1:4174` в Chrome/Edge. Для проверки или сборки используется штатный Node.js:

```powershell
node --test tests/*.test.mjs
node build.mjs
```

`dist/START_FRAMEDATE.cmd` запускает portable-папку при наличии Node.js в PATH. Нативный `.exe` в этой среде не упакован; это зафиксированное ограничение поставки.

## Рабочий цикл

1. При запуске открыт авторский синтетический пример с двумя ударами.
2. Создайте новый приём или задайте корень SF4 и выберите «Загрузить снимок Bulwark». Импорт создаёт неизменяемый снимок и авторские копии Slash_1, Heavy_Slash, Low_Slash.
3. Импорт сразу создаёт для атакующих частей подвижные авторские капсулы и траекторию тела. Это стартовый постановочный пресет, а не импорт геометрии SF4; его можно править на сцене либо численно.
4. Настройте сценарий, проигрывайте/шагайте, сохраните JSON и экспортируйте самостоятельный HTML.

## Модель времени и прототип

Внутренняя симуляция работает в целых тиках 60 Гц, окна — `[start, end)`. Импортное преобразование использует `M = (MidFrames ?? 1) + 1`: исходный `[S,E]` становится `[(S−1)×M,E×M)`, с вычитанием начала нарезанного клипа перед умножением. Частота отображается отдельно: три кадра 30 FPS — 6 тиков/100 мс, 60 FPS — 3 тика/50 мс. Переключение представления не изменяет движение.

Коллизия — дискретная проверка расстояния отрезков капсул с погрешностью `1e-7`, касание считается контактом. Одна группа Attack подтверждает лишь один контакт (устойчивый порядок: ID атакующей, затем цели). После контакта K остановка идёт на K+1…K+H, затем stun; действия цели снова доступны на `K+1+H+S`. Отталкивание — авторское линейное правило.

**Граница достоверности.** Профиль «Прототип», геометрия и реакции авторские. Импортированные damage, impulse, slowmo, hit-теги и YAML-интервалы хранятся и экспортируются, но не выдают расчёт SF4 за точную фреймдату.

## Импорт и ограничения

Импорт структурно читает YAML Settings/Triggers/Hits/Reactions, сохраняет параметры Attack и контрольные суммы. В рабочем каталоге первой итерации показаны только `Attack`, `Transitional`, `Throwable`, `Blocking` и `Unbreakable`; другие исходные интервалы остаются в снимке источника, но не попадают в авторскую версию. Для `.bin → .bytes` выполняется однозначный поиск без учёта регистра, проверяется magic, блоки, кадры, кости и границы ожидаемой минимальной структуры. Текущий Heavy должен сообщить 147 отсчётов, 102 кости, 2 блока.

Не входят: декодирование поз/моделей/SObjPart, геометрия из настоящих игровых ресурсов, интерпретатор условий и триггеров, парные анимации Low Slash, экспорт обратно в игру, точная физика/урон SF4, несколько целей и редактор FX. Указанные ограничения отображаются в приложении и HTML.
