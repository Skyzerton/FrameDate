Реализуй маленький прототип FrameDate внутри Unity Editor. Работай в текущем проекте `D:\_ACTIVE PROJECTS\FrameDate`, Unity 6000.2.14f1.

Сначала прочитай `docs/UNITY_PROTOTYPE_SPEC.md`. Это единственный актуальный объём этой реализации. Прежние ТЗ, README и отчёты браузерной версии описывают отменённый большой скоуп; не реализуй их требования. При наличии skill `unity-mcp-orchestrator` прочитай его и используй для работы с Unity MCP.

Нужно только: один куб тела, одна атакующая капсула, их независимое движение через обычный AnimationClip и стандартное окно Animation, один активный интервал, 30/60 FPS, подсветка активности, компактная панель FrameDate и сохранение штатными средствами Unity. Используй Scene View, Inspector, Animation Window и Undo. Для панели достаточно EditorWindow + IMGUI. Не создавай свой таймлайн, движок ключевых кадров или вторую систему часов.

До изменений проверь через доступные MCP-инструменты список/состояние редакторов и путь проекта. При нескольких экземплярах выбери именно FrameDate. Убедись, что Unity не компилирует код и готова принимать команды. Наличие MCP-пакета в manifest само по себе не доказывает, что соединение работает. Схемы инструментов и публичные Unity API проверяй по доступной документации и reflection; не копируй непроверенные вызовы из примеров.

Реализуй один рабочий цикл целиком: открыть демонстрацию → изменить ключи → изменить интервал → просмотреть кадры → сохранить. Обычные технические решения принимай самостоятельно. Работай внутри `Assets/FrameDate`; сохрани существующие пользовательские ассеты и настройки. Не меняй версию Unity и установленные пакеты без необходимости. Репозиторий SF4 не трогай.

Не добавляй импорт, столкновения, цель, реакции, несколько ударов, полный список окон, FX, экспорт или сборку exe. После выполнения шести проверок из ТЗ остановись; расширять продукт в этом задании не требуется.

После изменений C# дождись окончания компиляции и проверь Console. Используй подключённый Editor, не запускай второй Unity на ту же папку проекта. Реально открой сцену и панель, проверь шаги Animation Window, сделай визуальную проверку Scene View. Проверь, что preview не записывает лишние ключи и не портит базовое состояние сцены. Для операций, которые нельзя проверить через доступные инструменты, явно укажи «не проверено», а не выдавай наличие кода за успешную проверку.

Передай готовую демонстрацию и короткую инструкцию `docs/UNITY_QUICKSTART.md`. В финале укажи, как открыть инструмент, результаты всех шести проверок и оставшиеся проблемы. Не останавливайся после плана или генерации скриптов: нужен работающий минимальный инструмент в редакторе.
