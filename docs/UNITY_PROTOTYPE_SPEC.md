# FrameDate — первый прототип в Unity Editor

Версия 1.0. Этот документ заменяет прежний объём первой итерации. Старые ТЗ, разбор Bulwark и отчёты браузерной версии — справочные материалы, их функции не нужно добавлять в этот прототип.

## 1. Одна задача

Дать дизайнеру возможность поставить движение **одного куба тела и одной атакующей капсулы**, задать **один активный интервал** и посмотреть результат по кадрам. Главный вопрос прототипа: удобно ли так придумывать движение приёма?

Это инструмент **внутри Unity Editor отдельного проекта FrameDate**, без сборки отдельного приложения. Работаем в текущем `D:\_ACTIVE PROJECTS\FrameDate`, Unity **6000.2.14f1**. Пакет Unity MCP уже указан в проекте; доступность соединения разработчик проверяет перед работой.

## 2. Использовать готовые средства Unity

| Задача | Решение |
|---|---|
| Сцена, выделение, перемещение | Стандартные Scene View, Hierarchy и инструменты Transform |
| Ключи и кривые движения | Стандартное окно **Animation**, обычный `AnimationClip` |
| Проигрывание и переход по кадрам | Управление в том же окне Animation |
| Параметры удара и статус | Одна компактная панель `FrameDate` на `EditorWindow` + IMGUI |
| Хранение | Сцена, `.anim` и небольшой `ScriptableObject` с настройками приёма |
| Отмена правок | Штатные Undo/redo Unity; правки собственных полей подключить к ним |

**Не создавать собственные таймлайн, редактор кривых, систему ключей, файловый браузер или систему воспроизведения.** Пакет Timeline для этой задачи не использовать. Внешние UI-пакеты, npm и .NET-приложение не нужны. Установленные пакеты проекта без необходимости не менять.

## 3. Что пользователь делает

1. Открывает демонстрационную сцену и панель через меню `Tools > FrameDate`.
2. Выбирает пример приёма. В Scene View видны куб и капсула, в Animation — их ключи.
3. Меняет перемещение тела и локальное перемещение капсулы обычными средствами Animation и Scene View.
4. В панели задаёт начало и конец активности капсулы.
5. Перемещает курсор времени, шагает по кадрам или запускает проигрывание. Видит движение, номер текущего кадра, время в секундах и статус «Активна / Неактивна».
6. Сохраняет изменения штатным сохранением Unity. После повторного открытия получает тот же приём.

Предусмотреть простую команду создания нового такого же примитивного приёма с выбором **30 или 60 FPS**. Это может быть кнопка в панели с обычным диалогом сохранения Unity. Библиотека, поиск и менеджер версий не требуются.

## 4. Минимальные данные и сцена

Настройки приёма содержат имя, ссылку на обычный `AnimationClip` и две целочисленные границы активного интервала. Частота берётся из `clip.frameRate`, длительность — из клипа; отдельные конкурирующие значения не хранить.

Движение задаётся двумя независимыми наборами кривых в одном клипе:

- положение тела относительно неподвижного корня приёма;
- положение и при необходимости поворот капсулы относительно тела.

Удобная иерархия: неподвижный корень приёма → объект тела → визуальный куб и капсула. Размер визуального куба не должен масштабировать капсулу: куб — отдельный дочерний объект, движение задаётся его родителю. Контроллер анимации, если необходим стандартному окну Animation, создаётся автоматически и остаётся простым.

Рабочий вид — сбоку, движение в X/Y, глубина Z=0. Использовать стандартные примитивы. У капсулы достаточно постоянного размера и обычного Transform; две отдельные траектории её концов пока не нужны. Кости, скелет, реальные модели и игровая геометрия отсутствуют.

Достаточна структура `Assets/FrameDate/` с подпапками для Editor-кода, простых данных/компонентов и Demo-ассетов. Не создавать многослойную платформу расширений или универсальный редактор сущностей.

## 5. Время и активность

- Кадры нумеруются с **0**. Активность — `[startFrame, endFrame)`: начало включено, конец исключён. Это явно написано рядом с полями.
- Пример: `[20,30)` при 60 FPS активен на кадрах 20–29, неактивен на 19 и 30.
- Время кадра `f` равно `f / clip.frameRate`. Три шага 30 FPS занимают 0.1 секунды; три шага 60 FPS — 0.05 секунды.
- FPS выбирается при создании клипа. Конвертация готового приёма между 30 и 60 FPS не входит в прототип. Если частоту поменяли непосредственно в Unity, панель читает фактическое значение и показывает актуальные секунды; активные границы остаются номерами кадров.
- Единственный источник позиции воспроизведения — стандартное окно Animation для выбранного клипа/объекта. Панель не заводит вторые часы. При проигрывании активность можно проверять по времени относительно `startFrame / fps` и `endFrame / fps`; при шаге по кадрам границы должны совпадать точно.
- Не использовать скорость `Update` или физический шаг как частоту анимации. Здесь нет отдельного боевого времени, `MidFrames`, hitstop и игровой нормализации в 60 Гц: импорт источников пока отсутствует.
- Некорректный диапазон (`start < 0`, `end <= start`, конец за длительностью клипа) показывать как ошибку, не исправлять молча. Отсутствующий клип и неподдержанный FPS также объяснять пользователю.

При активном интервале капсула явно выделена цветом или контуром; вне интервала остаётся видимой для редактирования. Текстовый статус дублирует цвет. Подсветка зависит от просматриваемого времени и не записывается в анимационные ключи.

Если окно Animation закрыто или показывает другой объект/клип, панель сообщает, что нужно выбрать. Не показывать устаревший кадр как актуальный. Для подключения использовать публичные API текущей версии Unity; проверить доступные члены `AnimationWindow` через MCP/reflection или официальную документацию, не полагаться на выдуманный API.

## 6. Сохранность редактирования

Стандартное окно Animation отвечает за редактирование и preview клипа. Код FrameDate не должен одновременно независимо сэмплировать тот же объект и спорить с этим preview. Выход из preview должен восстанавливать базовое состояние средствами Unity.

Изменение своих настроек регистрировать через Undo и помечать соответствующий ассет изменённым. Простое проигрывание, перемещение курсора и изменение подсветки не должны оставлять новые ключи, изменённые материалы или постоянно загрязнять сохранённую сцену. Ссылки между сценой, клипом и настройками должны переживать сохранение и перезагрузку скриптов.

## 7. Демонстрация и шесть проверок готовности

Поставить готовую демонстрацию: клип 60 FPS длительностью 1 секунда, тело перемещается вправо, капсула дополнительно движется относительно тела. Несколько ключей достаточно; активный интервал `[20,30)`. Это авторский пример, не атака Bulwark.

| № | Проверка | Ожидаемый результат |
|---|---|---|
| 1 | Открыть проект, сцену и `Tools > FrameDate` | Работает в Edit Mode, видны куб/капсула, нет ошибок компиляции и новых ошибок инструмента в Console |
| 2 | Изменить ключ тела, затем ключ капсулы в Animation | Движения редактируются независимо; изменения сразу видны в Scene View |
| 3 | Открыть/создать клипы 30 и 60 FPS | Отображаемая частота соответствует клипу; кадр 3 соответствует 0.1 и 0.05 секунды соответственно |
| 4 | В демонстрации выбрать кадры 19, 20, 29, 30 | Неактивна, активна, активна, неактивна; статус и подсветка совпадают |
| 5 | Проиграть, вернуться назад и снова выбрать тот же кадр | Поза и активность совпадают; проверка не зависит от истории проигрывания и не создаёт ключей |
| 6 | Изменить границы, выполнить Undo/redo, сохранить, переоткрыть | Границы и анимационные ключи сохранены, ссылки целы; preview не испортил базовую сцену |

Для математической проверки границ допустим один небольшой Edit Mode тест. Главное — реально открыть инструмент и проверить редактирование через Unity, а не ограничиться компиляцией или автоматически созданными ассетами.

## 8. Строго за пределами прототипа

Цель и коллизии; правило контакта на удар; реакции, блок, урон и преимущество; несколько ударов/капсул; каталог окон состояний; импорт YAML/`.bytes`/моделей SF4; синхронизация репозиториев; FX; HTML/PDF/видео-экспорт; самостоятельный `.exe`; собственный визуальный стиль редактора.

Все эти возможности отложены. Разработчик не должен возвращать их из старых документов. Сам игровой репозиторий SF4 этому прототипу не нужен.

## 9. Результат работы разработчика

Готовая сцена, клип и настройки примера; минимальный C#-код инструмента; короткая инструкция `docs/UNITY_QUICKSTART.md` с меню и порядком действий; статусы шести проверок «проверено / не работает / не проверено» с фактическими результатами. Для проверки вида нужен снимок Scene View; он не заменяет проверку окна Animation и панели FrameDate.

Работа завершена, когда пользователь может открыть пример, изменить ключ и активный интервал, увидеть результат и сохранить его. План, отдельные классы без рабочего окна или красивый скриншот без редактирования не являются готовым прототипом.
